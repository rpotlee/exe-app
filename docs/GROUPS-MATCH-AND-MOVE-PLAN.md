# Groups match and move plan

The approved Groups page already projects user Outcomes/Tasks and saved AI group suggestions through `missionGroups`. Raw pending to-dos and loose Tasks appear in Ungrouped. The existing organization review only compares four captures within one batch and cannot assign entries to an established group.

1. Add one explicit **Match Ungrouped** action on Groups. It freezes the current Ungrouped entry IDs, sends bounded batches of four to the existing `ai-review` Edge Function, and reports progress. Page navigation and ordinary edits make no provider calls. The existing admission gate, model routing, per-user/system budgets, provider quotas, and request coordinator remain in use. A rate limit or outage stops safely; pressing the action again resumes against the remaining Ungrouped entries.
2. Add a strict group-match prompt/parser to the existing provider module. The server reads current source text and active candidate Outcomes by owner, validates IDs/revisions, and returns only clear matches to existing groups. Ambiguous entries remain Ungrouped. Cache validated results in `ai_intelligence` under a purpose-specific dedupe key and record applied matches in Activity. This adds no service or parallel grouping engine.
3. Add pure domain commands that move one entry manually or apply one validated match batch. A pending capture becomes a Task under the chosen Outcome using the existing approval writes; a loose Task changes `outcome_id`. A manual move may create a new Outcome through the existing model. Revision checks, target validity, a `tasks.group_manual` marker, and Activity events protect user corrections. Suggested groups and existing assignments are never overwritten by the AI sweep.
4. Add a compact move control to group-detail task rows and a shared move dialog with existing groups, Ungrouped, and New group. Keep the approved Groups overview layout; add only one small match control and its status.
5. Test parser/schema, stale and unauthorized response handling, batch behavior with 300 entries, manual overrides, provider errors, and current UI. Run typecheck, unit/database suites, Deno check, build, and browser smoke.

## Implemented and verified

The match action is user-triggered and runs while the Groups page is open. It does not silently create new groups or guarantee a match for unrelated work. New groups remain an explicit user choice. The `group_manual` migration is nullable during rollout so older clients' generic write RPC can still insert tasks. All new clients write an explicit boolean.

The browser sends only source and group IDs. The Edge Function reads owner-scoped current text and revisions, uses the existing analysis model and provider admission, validates the response, checks freshness again, and stores a purpose-specific result. The client applies at most four matches per workspace command and skips any entry or target whose revision changed. A manually moved task is excluded from later AI matching, including when moved back to Ungrouped. The run stops on provider budget, rate limit, or outage errors; remaining entries can be retried with another click.

Verification: TypeScript typecheck, 244 unit tests, 27 database tests, Deno Edge Function check, and production Vite build passed. The mobile local demo was exercised for AI matching to an existing group, moving to Ungrouped, and moving to a new group. The screenshot is [`artifacts/groups-match-mobile.jpg`](../artifacts/groups-match-mobile.jpg). Existing mock workload tests cover 300 mixed imports, 50 edits, 20 interactive requests, and provider usage accounting. No paid provider call was made in this environment. `npm run check:supabase` requires local VITE Supabase environment values and could not run without them.

## Deployment and limits

Apply `20261110000017_group_manual.sql`, deploy the updated `ai-review` Edge Function, then deploy the frontend build. The migration is safe with the previously deployed frontend. No new paid service is required. Matching compares against at most 40 active groups in the selected scope, four sources per request. A 300-task run may pause at configured budgets or provider rate limits; pressing Match Ungrouped again resumes against tasks still eligible. The explicit match operation is interactive while the page is open; the existing durable organization jobs remain separate. The local demo uses a deterministic fake matcher and does not establish live provider quality or cost.
